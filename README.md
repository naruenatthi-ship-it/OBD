# Deepal S05 OBD: อ่านค่าแบตเตอรี่ผ่านกล่อง ELM327

สคริปต์ Python สำหรับอ่านข้อมูลแบตเตอรี่ไฟฟ้าแรงสูงของ Deepal S05 ผ่านกล่อง ELM327
ที่ราคาไม่แพง (ไม่ต้องใช้เครื่องสแกนเฉพาะรุ่น) ค่าเริ่มต้นตั้งไว้สำหรับรุ่น **Max แบต 56.1 kWh** ที่ขายในไทย

คำสั่ง (PID/DID) และสูตรมาจากโปรเจกต์
[jpires71/Deepal_S05_PIDs](https://github.com/jpires71/Deepal_S05_PIDs) ซึ่งทดสอบกับรถแบต 68.8 kWh
**ยังไม่ได้ยืนยันกับรถสเปกไทย** ต้องลองกับรถจริงและเทียบค่ากับหน้าจอรถก่อน

> **ความปลอดภัย:** โปรแกรมนี้ส่งได้แค่คำสั่งอ่านค่า (UDS `0x22` ReadDataByIdentifier),
> สลับโหมดวินิจฉัยปกติ/ขยาย (`10 01`/`10 03`) และ TesterPresent (`3E 00`)
> โค้ดจะปฏิเสธคำสั่งเขียนค่า ลบโค้ด รีเซ็ต ECU ปลดล็อก หรือสั่งงานใดๆ ทั้งสิ้น
> แต่การใช้งานเป็นความเสี่ยงของผู้ใช้เอง

## ค่าที่อ่านได้ (ECU แบตเตอรี่ BMS, header `7A1` → ตอบที่ `7A9`)

| ค่า | คำสั่ง | สูตร | สถานะสูตร |
|---|---|---|---|
| SOC (%) | `22F22F` | `A` | ยืนยันแล้ว |
| แรงดันแพ็ก (V) | `22F228` | `(A*256+B)/10` | ยืนยันแล้ว |
| กระแสแพ็ก (A) | `22F229` | `((A*256+B)-6015)/10` | ยืนยันแล้ว |
| แรงดันเซลล์สูงสุด/ต่ำสุด (V) | `22F250` / `22F251` | `(A*256+B)/1000` | ยืนยันแล้ว |
| อุณหภูมิแบตสูงสุด/ต่ำสุด (°C) | `22F252` / `22F253` | `A-40` | ยืนยันแล้ว |
| อุณหภูมิหัวชาร์จ (°C) | `22F255` | `(A-32)/1.8` | รอยืนยัน |
| SOH (%) | `22F27D` | `(A*65536+B*256+C)/10000` | รอยืนยัน |
| SOC สูตร README | `22F231` | `(A*256+B)/10` | รอยืนยัน |
| พลังงานคงเหลือ (kWh) | `22F264` | `ความจุ-(A*256+B)/1000` | ทดลอง |
| รอบชาร์จเต็ม EFC | `22F27F` | `ค่า 4 ไบต์/1000000/ความจุ` | ทดลอง |

ค่าที่โปรแกรมคำนวณเพิ่มให้: กำลังแพ็ก (V×I), ส่วนต่างแรงดันเซลล์ (mV), ส่วนต่างอุณหภูมิแบต

## อุปกรณ์

- กล่อง ELM327 **ของแท้หรือชิปดี** เช่น Vgate iCar Pro (บลูทูธ/WiFi) หรือ vLinker
  กล่องโคลนราคาถูกมากมักส่งคำสั่ง UDS แบบนี้ไม่ได้
- คอมพิวเตอร์ Windows / Linux / macOS ที่ติดตั้ง Python 3.8 ขึ้นไป

## ติดตั้ง

```bash
pip install -r requirements.txt
```

## วิธีใช้กับรถ

1. เสียบกล่องที่ช่อง OBD (ใต้คอนโซลฝั่งคนขับ) แล้วกดสตาร์ทรถให้ขึ้น READY
2. เชื่อมต่อกล่อง
   - **บลูทูธบน Windows:** จับคู่ในหน้าตั้งค่า Bluetooth แล้วดูหมายเลข COM ใน
     Device Manager → Ports (เช่น `COM5`)
   - **บลูทูธบน Linux:** `sudo rfcomm bind 0 <MAC กล่อง>` แล้วใช้ `/dev/rfcomm0`
   - **WiFi:** ต่อ WiFi ของกล่อง แล้วใช้ `socket://192.168.0.10:35000`
     (IP/port ดูได้จากคู่มือกล่อง)
   - **USB:** `COM3` หรือ `/dev/ttyUSB0`
3. ตรวจว่ารถตอบไหม:

```bash
python -m deepal_s05 --port COM5 check --save check.json
```

4. ดูค่าสดและบันทึกเป็น CSV:

```bash
python -m deepal_s05 --port COM5 live --interval 2 --csv battery_log.csv
```

ตัวเลือกอื่น: `--capacity 68.82` ถ้าเป็นรุ่นแบตใหญ่, `-v` แสดงคำสั่งและคำตอบดิบ,
`--baud 115200` ถ้ากล่อง USB ใช้ความเร็วอื่น

### เช็กว่าค่าถูกต้องกับรถคุณ

- **SOC** ต้องตรงกับ % บนหน้าจอรถ ถ้า `22F22F` ไม่ตรง ให้ดู `22F231` แทน
- **แรงดันแพ็ก** ควรอยู่ราว 300–400 V
- **กระแส** ตอนจอดนิ่งควรใกล้ 0 A และต้องเปลี่ยนเมื่อเปิดแอร์
  ถ้าค่าเพี้ยนไปเท่าเดิมตลอด แปลว่า offset `6015` อาจไม่ตรงกับรถไทย
- **แรงดันเซลล์** แบต LFP ควรอยู่ราว 3.2–3.4 V และส่วนต่างระหว่างเซลล์ควรเป็นหลักไม่กี่ mV
- **SOH** รถใหม่ควรได้ราว 97–100%

## หาข้อมูลใหม่ (แรงดันรายเซลล์, อุณหภูมิ OBC ฯลฯ)

ทุกคำสั่งในส่วนนี้ส่งแค่คำสั่งอ่าน (`22`), สลับโหมดวินิจฉัย (`10 01`/`10 03`) และ
TesterPresent (`3E 00`) โค้ดจะปฏิเสธคำสั่งอื่นทั้งหมด ควรทำตอน**จอดรถอยู่**เท่านั้น

### 1. สแกนหา ECU ทั้งหมดในรถ

```bash
python -m deepal_s05 --port COM5 ecus --save ecus.csv
```

ไล่ถามทุก header `700`–`7FF` (ประมาณ 1–2 นาที) แล้วแสดง ECU ที่ตอบ
พร้อมรหัสชิ้นส่วนและเวอร์ชันซอฟต์แวร์ ใช้ดูว่า ECU ไหนน่าจะเป็น OBC, มอเตอร์ หรืออินเวอร์เตอร์
ถ้าจะหา OBC ให้ลองตอน**เสียบชาร์จ AC** เพราะ OBC อาจปิดตัวตอนไม่ได้ชาร์จ

### 2. สแกนหาค่าใน ECU

```bash
python -m deepal_s05 --port COM5 discover --header 7A1 --start F200 --end F2FF --save dids.csv
```

- ไล่อ่าน DID ทีละตัวและแสดงค่าที่ตอบกลับ
- ถ้าเจอคำตอบที่มีค่าหลายตัวอยู่ในช่วงแรงดันเซลล์ (2.5–4.3 V) เรียงกัน จะขึ้น
  `** อาจเป็นแรงดันรายเซลล์`
- ใส่ `--extended` เพื่อเข้าโหมดวินิจฉัยขยายก่อนอ่าน บางค่าอ่านได้เฉพาะโหมดนี้
- ช่วงที่น่าลอง: `F100–F1FF`, `F200–F2FF`, `F300–F3FF`, `0100–01FF`
  (ช่วงละ 256 DID ใช้เวลาประมาณ 1–2 นาที)

### 3. ดักฟังตอนเครื่องสแกนของอู่อ่านค่า (ได้ผลชัวร์ที่สุด)

```
รถ ── ช่อง OBD ── สายแยก 1 ออก 2 ─┬── เครื่องสแกนของอู่
                                  └── กล่อง ELM327 + โน้ตบุ๊ก (ฟังอย่างเดียว)
```

```bash
python -m deepal_s05 --port COM5 sniff --out sniff.log
```

1. เริ่ม `sniff` ก่อน แล้วให้ช่างเปิดหน้าข้อมูลที่ต้องการในเครื่องสแกน
   (เช่น แรงดันรายเซลล์ หรือข้อมูล OBC) ทิ้งไว้สัก 10–20 วินาที แล้วกด Ctrl+C
2. ดูสรุปว่าเครื่องสแกนส่งคำสั่งอะไรไปที่ ECU ไหน และได้คำตอบอะไร:

```bash
python -m deepal_s05 analyze sniff.log
```

- กล่องจะอยู่ในโหมดเงียบ (`ATCSM1`) ไม่ส่งอะไรเข้ารถเลย
- ถ้าขึ้นว่า "กล่องรับไม่ทัน" ให้แคบตัวกรองลง เช่น ดูเฉพาะ BMS ด้วย
  `--filter 7A1 --mask 7F7`
- ส่งไฟล์ `sniff.log` มาให้ช่วยวิเคราะห์ต่อได้

## ทดสอบบนคอมโดยไม่ต้องมีรถ (ELM327-emulator)

```bash
pip install ELM327-emulator
python emulator/run_emulator.py            # เปิดตัวจำลองที่ TCP port 35000
python -m deepal_s05 --port socket://localhost:35000 check   # รันในอีกหน้าต่าง
```

ข้อมูลในตัวจำลอง (`emulator/deepal_s05_scenario.py`) เป็นค่าที่แต่งขึ้นเพื่อทดสอบ ไม่ได้มาจากรถจริง
รวมถึง DID แรงดันรายเซลล์ `22F2A0` และ ECU ตัวที่สองที่ `761` (สมมติเป็น OBC)
ซึ่งมีไว้ทดสอบคำสั่ง `discover` และ `ecus` เท่านั้น ของจริงยังไม่รู้ว่าอยู่ที่ไหน
ใช้ `--interface 0.0.0.0` ถ้าจะให้แอปบนมือถือในวง WiFi เดียวกันต่อเข้ามาทดสอบ
